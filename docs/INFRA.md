# Landlords — инфраструктура и деплой

Инфраструктура рассчитана на локальный Docker Compose. Для настоящего продукта не хватает воспроизводимой **online**-сборки (CI / чужая машина), нормального CI и одного входа в прод.

Офлайн-сборка с копированием `.venv` — осознанный режим (нет доступа к PyPI на машине сборки). Его не убирать; рядом нужен online-путь из `requirements.txt`.

Продуктовый порядок: [ROADMAP.md](./ROADMAP.md) · чеклист: [PRIORITIES.md](./PRIORITIES.md).

---

## Что уже есть

В `docker-compose.yml` собраны API, Celery worker и beat, Postgres 15, Redis 7, nginx. Flower вынесен в профиль `development` и наружу не торчит. У API есть `/health`, `/ready` (база и Redis) и `/metrics`. Sentry и Prometheus-клиент в коде подключены. Документы лежат в общем volume `storage/documents` у API и воркера. Для разработки `docker-compose.override.yml` монтирует исходники и включает `--reload`.

---

## Что не является продом

**Образ бэкенда собирается только офлайн-путём.** `backend/Dockerfile` копирует `.venv/lib/.../site-packages` с машины, где venv уже собрали. Это нормально для air-gapped сборки, но на чистом CI или другом компьютере без готового `.venv` сборка падает. Нужен второй режим: `pip install -r requirements.txt` внутри образа (см. порядок ниже). Offline-путь с `.venv` остаётся.

**Фронт в прод-профиле не соберётся.** `frontend/Dockerfile` пустой, а сервис `frontend` в compose всё равно делает `build`. При этом и nginx, и этот сервис хотят порт `80`. Статику должен отдавать nginx, отдельный контейнер на том же порту не нужен.

**CI проверяет только кусок бэкенда.** В `.github/workflows/ci.yml` стоят узкий `ruff` и `pytest` по `tests/unit` и `tests/tasks`. Нет интеграционных тестов, нет `tsc` и сборки фронта, нет сборки образа (online). Зелёный пайплайн не значит, что проект поднимается.

**Секреты и сеть — от локальной разработки.** `.env.example` пустой. Postgres и Redis опубликованы на хост с паролем `postgres`. `DEBUG` по умолчанию `true`. В nginx CORS зашит на `http://localhost:3000`, заголовок HSTS стоит на голом HTTP, TLS нет. `/health` у nginx смотрит только в liveness API, не в `/ready`.

**Данные нечем восстановить.** Документы — bind-mount на диск сервера. В `backend/TODO.md` бэкап отмечен готовым, файла с процедурой в репозитории нет. Миграции при старте контейнера не накатываются: их нужно гонять руками.

**Воркеры слабо наблюдаются.** У beat healthcheck выключен. У worker проверка — одноразовый Python-вызов, не признак того, что очередь жива. Метрики никто не скрейпит, алертов нет.

## Что поменять, по порядку

### 1. Образ — два режима сборки

| Режим | Когда | Как |
|-------|-------|-----|
| **offline** (оставить) | нет PyPI на машине сборки | `COPY .venv/.../site-packages` — заранее `.venv` на Python 3.12, совместимый с базовым образом |
| **online** (добавить) | CI, чистая машина, есть сеть | `pip install -r requirements.txt` внутри образа |

Сделать через build-arg (`INSTALL_MODE=offline|online`) или отдельный Docker target. Offline — first-class, не «временный костыль».

Общее для обоих режимов:

- непривилегированный пользователь (уже есть);
- в online-контексте не тащить `.venv`, тесты и `.env` (`.dockerignore`);
- команда старта: `alembic upgrade head`, затем uvicorn;
- healthcheck на `/ready` (не только `/health`).

### 2. Один вход

Nginx проксирует `/api` на API и отдаёт собранный Vite. Порт снаружи — только 80/443. Postgres и Redis без `ports` на хост в prod. Пароли и `SECRET_KEY` только из env; `.env.example` с пустыми значениями и комментариями. Убрать конфликт: отдельный сервис `frontend` на порту 80 не нужен.

### 3. CI

Поднять Postgres и Redis в job, прогнать integration, `npm run build`, собрать backend-образ в **online**-режиме (`pip install`). Деплой — отдельным шагом, не в том же job, что тесты. Offline-сборку CI не обязан гонять; её проверяешь локально перед выкладкой без сети.

### 4. TLS и почта

Сертификат на nginx (Caddy или certbot). SMTP в env; без него прод не стартует (или явный `ALLOW_INSECURE_EMAIL=1` только для self-hosted). CORS — origin реального фронта, не localhost.

### 5. Данные

Ежедневный дамп Postgres и копия `storage/documents` (или S3/MinIO вместо диска). Один раз восстановить бэкап на пустую машину и записать команды в [deploy.md](./deploy.md) (создать при первом прогоне).

### 6. Наблюдаемость

`/ready` в healthcheck API. Sentry DSN в проде. Алерт, если beat не создал начисления или кончилось место под документы. Prometheus можно оставить на потом: эндпоинт уже есть.

---

## Чего не делать сейчас

Kubernetes, несколько реплик API и отдельный кластер Redis ничего не меняют, пока online-образ не собирается в CI и бэкапа нет. Офлайн-`.venv` не выкидывать «ради чистоты» — он нужен для твоей сборки без сети.
